Executive Summary

This document constitutes the official technical delivery for the AI Engineer Full Stack selection process at Artefact. The project delivers an end-to-end conversational customer support system for Empório da Música, a musical instrument retail store in Campo Grande, MS, Brazil. The solution relieves human attendants from high-frequency inquiries (business hours, address, order shipment tracking, catalog search with budget filters, installment rules, and return policies) through a resilient, auditable AI architecture.

1. Architecture and Technical Decisions

The project was engineered around six fundamental software and AI engineering decisions to ensure high reliability, low operational costs, deterministic business policy compliance, and exceptional user experience:

1.1. Agent Orchestration: LangChain ReAct Pattern (LangGraph)

  • Implementation: Built with langgraph.prebuilt.create_react_agent, the established standard for agentic architectures in LangChain.
  • Architectural Rationale: The ReAct (Reasoning + Acting) loop alternates between Thought, Action, and Observation phases. Bound to typed Pydantic tools (@tool), it enables multi-step tool composition (e.g., cross-referencing store return policies and relational customer order records within a single user turn) while providing full auditable introspection into intermediate reasoning.

1.2. LLM Provider Strategy and Resilience

  • Primary Model: Google Gemini (gemini-3.5-flash-lite) via langchain-google-genai.
  • Fallback Model: OpenAI (gpt-4o-mini), configurable via environment variables without code modification.
  • Deterministic Offline Engine: High-speed mock provider for continuous integration (CI/CD) and automated unit testing without API costs or rate-limiting.
  • Architectural Rationale: Gemini 3.5 Flash Lite achieves sub-second response times, excellent native Portuguese tool calling, and high cost efficiency for transaction-dense conversational workloads. The decoupled provider layer applies dependency inversion: switching providers requires editing only the .env file.

1.3. Data Engineering (ETL) and Relational Persistence Layer

  • ETL Data Processing (app/db/etl.py):
    • Unicode Normalization: NFKC text standardization and whitespace stripping across all operational datasets.
    • Monetary Precision: Strict floating-point decimal casting and 2-decimal rounding for prices, discounts, and order amounts.
    • Inventory Constraints: Enforcement of non-negative stock invariants (stock_quantity >= 0).
    • Specification Parsing: Robust parsing of raw JSON strings into typed technical specification dictionaries (tonewoods, fret count, pickups, electronics).
    • Campaign Segmentation: Strict binary partitioning between active promotions (is_active = 1) and expired promotions (is_active = 0), ensuring expired discounts are never applied.
  • Relational Database Design:
    • SQLite backend (data/emporio.db) with enforced foreign key integrity (PRAGMA foreign_keys = ON;) and composite indexes (idx_products_name, idx_products_category, idx_products_price, idx_orders_customer, idx_orders_tracking).
    • Session Persistence: Dedicated conversation_history table indexed by session_id, maintaining full client context across browser refreshes and server reboots.
    • Roadmap to Dockerized PostgreSQL: The data access layer is cleanly abstracted, enabling immediate migration to containerized PostgreSQL (docker-compose.yml) without touching route handlers.

1.4. Policy Retrieval Architecture (RAG)

  • Knowledge Source: Store Policies and Customer Service Manual (data/políticas_da_loja.pdf, Version 2.1).
  • Retrieval Strategy: Semantic domain retrieval categorizing operational hours, physical address, statutory 7-day right of withdrawal (CDC Art. 49), 90-day warranty procedures, local shipping thresholds, and non-cumulativity of the 5% PIX discount over active promotions.
  • Architectural Rationale: Prevents hallucination of critical legal deadlines and financial conditions by retrieving exact policy clauses directly into the agent prompt context.

1.5. Deterministic Scope Guardrails

  • Store Mandate: Empório da Música exclusively sells complete musical instruments and does not stock standalone accessories or amplification (loose strings, picks, cables, pedals, amplifiers, or standalone cases).
  • Implementation (app/agent/guardrails.py): Fast deterministic pre-LLM filter intercepting accessory queries and non-domain topics (programming, cooking recipes, politics) prior to model invocation. Emits polite refusals and redirects clients to regional partner shops.
  • Production Impact: 0 ms API latency, zero token consumption on invalid requests, and 100% deterministic scope adherence.

1.6. Frontend Architecture and Technology Stack

  • React 18 SPA: Functional component architecture with hooks (useState, useEffect, useRef, useMemo) for reactive message synchronization, active thread switching, and optimistic UI updates.
  • TypeScript: Formal interface contracts (Message, ChatSession, ChatResponse, HealthResponse) providing strict compile-time verification across client and server.
  • Tailwind CSS: Mobile-first utility design system featuring custom Artefact corporate accents (#E60067), collapsible animated sidebar (w-72 / w-0 with overflow-hidden), and high-contrast dark theme.
  • Marked.js: Real-time Markdown parser and compiler ensuring catalog pricing, installment schedules, and bulleted specs render with clean visual alignment.
  • HTML5 LocalStorage API: Preserves session identifiers and thread lists across page reloads (F5), reconciled with backend SQLite history.
  • Vector Branding & SVGs: Exact geometric reproduction of Artefact's chevron logo glyph (/\) and custom avatars for customer and AI assistant.

2. Setup and Execution Instructions

2.1. Prerequisites

Python 3.11 or higher (developed and verified on Python 3.12). Package management via uv (recommended) or pip.

2.2. Installation Commands

# 1. Clone repository
git clone https://github.com/augdev1/artefact_ai_fullstack.git
cd artefact_ai_fullstack

# 2. Setup virtual environment with uv (recommended)
uv venv .venv
uv pip install -e ".[dev]"

# Alternative using standard pip
python -m venv .venv
# On Windows: .venv\Scripts\activate | On Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"

2.3. Environment Configuration (.env)

LLM_PROVIDER=gemini
GEMINI_API_KEY=your_api_key_here
GEMINI_MODEL=gemini-3.5-flash-lite

# Optional Fallback Settings
OPENAI_API_KEY=your_openai_key_here
OPENAI_MODEL=gpt-4o-mini
DATABASE_PATH=data/emporio.db
HOST=0.0.0.0
PORT=8000

2.4. Server Execution

python -m app.main

5. Known Limitations and Production Roadmap

  1. PostgreSQL Migration via Docker: Complete the containerization of the persistence layer using official PostgreSQL images (postgres:16-alpine) in docker-compose.yml to provide connection pooling and concurrent write scaling.
  2. Dense Vector Embeddings (Hybrid Search): Integrate a vector database (pgvector or Qdrant) to enable acoustic timbre and musical style searches (e.g., "warm acoustic guitar for fingerstyle jazz").
  3. Production Observability & Tracing: Instrument the agent with OpenTelemetry or LangSmith for latency tracking, per-session token cost attribution, and prompt drift detection.
  4. Omnichannel Messaging & Audio Processing: Integrate the Meta WhatsApp Cloud API and deploy Whisper speech-to-text models to process customer voice notes.
